# Orbit v0.4.0 - Feuille de Route & Spécifications

Ce document formalise la feuille de route pour la version **v0.4.0** d'Orbit. Il intègre les fonctionnalités majeures de réseau (Bastion & Proxy) déjà fusionnées sur `develop`, les chantiers de stabilisation et de sécurité issus de la revue v0.3.0/v0.3.1, ainsi que la nouvelle fonctionnalité d'ouverture dans un terminal externe natif.

---

## 🎯 Stratégie de Release & Versioning

### Pourquoi v0.4.0 plutôt que v0.3.1 ?
1. **Ajout d'un sous-système réseau complet** :
   - Support du **Bastion SSH (Jump Host / ProxyJump)** avec tunneling direct TCP/IP via `russh`.
   - Support des **Proxies Réseau (SOCKS5 RFC 1928/1929 et HTTP CONNECT)** implémentés en Rust natif sans dépendance externe.
   - Chaînage dynamique `Orbit ➔ Proxy ➔ Bastion ➔ Cible`.
   - Ces ajouts architecturaux constituent un saut fonctionnel majeur qui dépasse le cadre d'un patch correctif (`0.3.1`) et justifie sémantiquement la **v0.4.0**.

2. **Philosophie de développement** :
   - Pas de branche monolithique `0.4` risquant de diverger.
   - Découpage en **branches dédiées et atomiques** basées sur `develop`, testées et revues indépendamment avant le bump final.

## 🛠️ Chantier 1 : Durcissement & Robustesse (`fix/transfer-hardening-v0.4`)

Branche : `fix/transfer-hardening-v0.4` depuis `develop`.

### 1.1 Permissions strictes des fichiers temporaires `.part` (Unix)
* **Problème** : Lors des téléchargements SFTP et S3, les fichiers `.part` sont créés avec le `umask` système (`0644`). Un utilisateur local pourrait lire les données en cours de transfert avant que `finalize_partial_download` n'applique les permissions finales (`0600`).
* **Fichiers** :
  - `src-tauri/src/sftp/client.rs`
  - `src-tauri/src/s3/client.rs`
* **Implémentation** :
  - Utiliser `std::os::unix::fs::OpenOptionsExt::mode(0o600)` sous `#[cfg(unix)]` dès la création du fichier temporaire.

### 1.2 Upload SFTP atomique avec protection contre l'écrasement partiel
* **Problème** : Si l'utilisateur choisit d'écraser un fichier distant en SFTP et que le transfert est annulé ou coupé à mi-parcours, le fichier distant original est tronqué et corrompu.
* **Fichiers** :
  - `src-tauri/src/sftp/client.rs`
* **Implémentation** :
  - Téléverser vers un fichier temporaire distant `.orbit-tmp-XXXX` dans le même répertoire.
  - À la fin du téléversement complet, renommer atomiquement (`rename`) vers le fichier cible.
  - Nettoyer le `.orbit-tmp-XXXX` en cas d'annulation ou d'erreur.
  - Fallback vers l'écriture directe si le serveur SFTP interdit les renommages (permissions strictes).

### 1.3 Pause / Reprise globale sur les dossiers (`GroupRow`)
* **Problème** : Dans la modale des transferts (`TransferProgressModal`), un groupe de dossier permet uniquement d'annuler tous les fichiers en bloc. La mise en pause nécessite de cliquer sur chaque fichier individuellement.
* **Fichiers** :
  - `src/components/modals/TransferProgressModal.tsx`
  - `src/store/useOrbitStore.ts`
* **Implémentation** :
  - Ajouter un bouton `Pause / Reprise` au niveau du header du groupe.
  - Propager l'action à l'ensemble des transferts du groupe dans le store.

### 1.4 Nettoyage propre lors de la déconnexion de session
* **Problème** : Déconnecter une session alors qu'un dialogue de conflit est ouvert ou que des transferts sont en cours d'enregistrement peut laisser l'UI ou des promesses orphelines.
* **Fichiers** :
  - `src/store/useOrbitStore.ts`
  - `src-tauri/src/sftp/commands.rs`
* **Implémentation** :
  - Rejeter/annuler proprement les dialogues de conflit actifs lors d'un `disconnect`.
  - Nettoyer la file d'attente associée à la session déconnectée.

### 1.5 Attestation de build SLSA dans la CI release
* **Fichiers** :
  - `.github/workflows/release.yml`
* **Implémentation** :
  - Intégrer `actions/attest-build-provenance` directement dans le job matriciel `build-release` pour attester les artefacts natifs in-situ avant publication.

## 🖥️ Chantier 2 : Ouverture dans un Terminal Externe (`feat/open-in-terminal`)

Branche : `feat/open-in-terminal` depuis `develop`.

### Philosophie ("Chacun son boulot")
* **Rejet de la solution terminal web embarqué** : Pas de `xterm.js` avec faux PTY émulé en Rust dans Orbit (gonflement inutile du bundle, problèmes de compatibilité de touches, d'encodage, de resize, etc.).
* **Approche native inspirée de WinSCP** : Orbit délègue la session interactive shell aux terminaux natifs de l'OS avec toute la puissance de leurs fonctionnalités (onglets, thèmes, polices, raccourcis).

### Spécifications fonctionnelles & techniques

#### 1. Commande Tauri Rust
* Commande : `open_in_external_terminal(profile_id: String, remote_path: Option<String>) -> Result<(), String>`
* Récupère la configuration du profil SFTP (hôte, port, nom d'utilisateur, chemin de clé SSH, proxy/bastion).
* Construit la ligne de commande SSH appropriée :
  ```bash
  ssh -p <port> <user>@<host> [-i <path_to_key>] [-J <bastion_spec>]
  ```
  *(Si `remote_path` est spécifié, passer `-t "cd <path> && exec \$SHELL -l"`)*.

#### 2. Adaptateurs par Système d'Exploitation
* **macOS** :
  - Support de `Terminal.app` par défaut (via `open -a Terminal <script>` ou AppleScript).
  - Support optionnel d'`iTerm2` si détecté ou configuré.
* **Windows** :
  - Priorité 1 : `Windows Terminal` (`wt.exe -d . ssh ...`) si présent.
  - Priorité 2 : `PuTTY` (`putty.exe -ssh -P <port> -l <user> -i <key>`) si présent.
  - Fallback : `PowerShell` (`powershell.exe -NoExit -Command "ssh ..."`) ou `cmd.exe`.
* **Linux** :
  - Détection automatique via `$TERMINAL`, `x-terminal-emulator`, `gnome-terminal`, `konsole`, `kitty`, ou `alacritty` (`<terminal> -e ssh ...`).

#### 3. Intégration dans l'interface utilisateur
* Bouton d'action dans la barre d'outils supérieure du panneau distant (à côté de l'arborescence / refresh).
* Raccourci contextuel (clic droit sur un dossier distant : "Ouvrir un terminal ici").
* Icône discrète et intuitive (icône de console / terminal).
* Visible uniquement pour les profils de type **SFTP** (masqué pour S3).

## 🚀 Chantier 3 : Préparation de la Release v0.4.0 (`release/v0.4.0`)

Branche : `release/v0.4.0` depuis `develop`.

1. **Montée de version synchronisée** :
   - `package.json` : `0.4.0`
   - `src-tauri/Cargo.toml` : `0.4.0`
   - `src-tauri/tauri.conf.json` : `0.4.0`
   - `Cargo.lock` / `package-lock.json`
2. **Rédaction du CHANGELOG v0.4.0** :
   - **Nouveau** : Prise en charge des Bastions SSH (Jump Hosts / ProxyJump).
   - **Nouveau** : Support complet des Proxies SOCKS5 (avec/sans authentification RFC 1929) et HTTP CONNECT.
   - **Nouveau** : Action "Ouvrir dans le Terminal" (Terminal.app, Windows Terminal, PuTTY, Linux).
   - **Amélioration** : Uploads SFTP atomiques (protection contre l'écrasement partiel).
   - **Sécurité** : Permissions strictes `0600` dès la création des `.part` temporaires sur Unix.
   - **UI** : Contrôle Pause/Reprise au niveau des groupes de transfert de dossiers.
   - **CI** : Attestations de provenance SLSA in-situ sur les binaires de release.
3. **Validation & Tag** :
   - Vérification de la suite de tests (`cargo test --all`, `npm test`).
   - Merge sur `develop`, puis merge sur `main` et création du tag `v0.4.0`.

## 🔮 Perspectives Long Terme (Post-v0.4.0)

Idées et besoins identifiés pour les versions ultérieures :

1. **Éditeur de texte / Visionneuse rapide intégrée** :
   - Double-clic sur un fichier texte/config pour l'ouvrir dans un éditeur léger intégré avec sauvegarde et re-téléversement automatique.
2. **Synchronisation bidirectionnelle de répertoires** :
   - Outil de comparaison et de synchronisation (miroir / source vers cible / mise à jour des fichiers plus récents).
3. **Chiffrement du coffre de configuration** :
   - Option de mot de passe maître pour chiffrer l'intégralité du fichier `profiles.json` local (en plus du stockage des clés et mots de passe dans le trousseau système).
4. **Nouveaux protocoles de stockage** :
   - WebDAV (Nextcloud / ownCloud).
   - Azure Blob Storage & Google Cloud Storage.
